# Security Policy

## Supported version

Security fixes target the latest published major version.

## Reporting

Use a private GitHub security advisory to report a vulnerability, exposed secret, unsafe authority path, or data-leak risk. Do not post sensitive details in a public issue.

Include the affected version, file or component, reproduction steps, impact, and the smallest safe test case. Never include real exchange credentials, wallet secrets, private keys, seed phrases, or personal data.

## Scope

The project is research-only. Any behavior that can place an order, connect a financial account, handle trading credentials, sign a transaction, or change external state is outside the intended design and should be treated as a security defect.
